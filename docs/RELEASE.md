# نسخه‌ی نهایی (Release) سابو

نسخه‌ی نهایی برنامه‌ای جدا از نسخه‌ی آزمایشی است:

| | نسخه‌ی آزمایشی | نسخه‌ی نهایی |
|---|---|---|
| شناسه | `ir.sabou.erp.debug` | `ir.sabou.erp` |
| نام روی گوشی | «سابو آزمایشی» | «سابو» |
| امضا | کلید عمومی debug (داخل مخزن) | **کلید خصوصی شما** (هرگز داخل مخزن نیست) |

این دو برنامه روی هم نصب نمی‌شوند و داده‌هایشان هم جداست. برای انتقال داده از نسخه‌ی آزمایشی به نسخه‌ی نهایی، در نسخه‌ی آزمایشی از «پشتیبان‌گیری و بازیابی» یک فایل پشتیبان بسازید و در نسخه‌ی نهایی همان را بازیابی کنید.

## ۱. کلید امضا (فقط یک بار)

همه‌ی به‌روزرسانی‌های بعدی باید با **همین** کلید امضا شوند. اگر کلید یا رمزش گم شود، اندروید به‌روزرسانی را نمی‌پذیرد و باید برنامه را پاک کنید و از پشتیبان بازیابی کنید. پس فایل کلید و رمزها را در دو جای امن نگه دارید، مثلاً یک فلش و یک مدیر رمز.

برای ساختن کلید روی کامپیوتری که Java دارد:

```bash
scripts/make_release_key.sh
```

این اسکریپت فایل `sabou-release.jks` را می‌سازد و مقدار چهار secret را نمایش می‌دهد.

## ۲. secretهای GitHub (فقط یک بار)

در مخزن به Settings › Secrets and variables › Actions › New repository secret بروید و این چهار secret را بسازید:

| نام | مقدار |
|---|---|
| `SABOU_KEYSTORE_B64` | محتوای فایل کلید به‌صورت base64 (اسکریپت آن را در `sabou-release.jks.b64` می‌نویسد) |
| `SABOU_KEYSTORE_PASSWORD` | رمز فایل کلید |
| `SABOU_KEY_ALIAS` | `sabou` |
| `SABOU_KEY_PASSWORD` | رمز کلید (اسکریپت آن را همان رمز فایل می‌گذارد) |

از این به بعد CI در هر اجرا یک APK امضاشده‌ی نهایی هم می‌سازد. این APK در بخش artifacts اجرا با نام `sabou-release-apk` قرار می‌گیرد.

## ۳. انتشار هر نسخه

1. در `version.properties` مقدار `VERSION_NAME` را بالا ببرید (مثلاً `0.3.0`) و `VERSION_CODE` را یکی زیاد کنید. این کار را با یک PR انجام دهید و ادغامش کنید.
2. یک tag هم‌نام نسخه بسازید و push کنید:

   ```bash
   git tag v0.3.0 && git push origin v0.3.0
   ```

   یا در تب Actions، گردش‌کار **release** را دستی اجرا کنید.
3. گردش‌کار release این کارها را انجام می‌دهد:
   - آزمون‌ها را اجرا می‌کند؛
   - APK را می‌سازد و امضا می‌کند؛
   - در بخش Releases، فایل `sabou-0.3.0.apk` را همراه `SHA256SUMS.txt` منتشر می‌کند.
4. روی گوشی‌ها APK را نصب کنید. نصب روی نسخه‌ی قبلی انجام می‌شود و داده‌ها می‌مانند. هر دو گوشی (اصلی و دوم) باید یک نسخه داشته باشند.

## بررسی نسخه‌ی کوچک‌شده (R8)

نسخه‌ی نهایی با R8 کوچک می‌شود. CI در هر اجرا همان ساخت را با کلید debug و نام «سابو بررسی نسخه» روی شبیه‌ساز نصب و اجرا می‌کند تا اگر کوچک‌سازی چیزی را خراب کرده باشد، پیش از انتشار معلوم شود (ADR-0048).
